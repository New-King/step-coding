## 1. 真实模型评测集（最该先做）

**为什么**：裁剪条数、截断阈值、提示词措辞，这些参数现在全靠手工跑一次看结果。
上次把提示词写成「要改文件前先 look」，结果模型开始反复读同一个文件，25 步打满、
7.9 万 token —— 是手工跑才发现的。没有评测集，改一次就要重来一遍这种排查。

**做什么**：

- 固定 6～10 个任务，覆盖：建单文件、建多文件、改一处、删文件、该提问、该拒绝、多轮追问、超范围。
- 每个任务断言：最终文件清单、关键文件里必须出现/不能出现的片段、步数上限、是否 `finish`。
- 输出一张表：任务 × (token / 步数 / 耗时 / 通过与否)。
- 放 `scripts/eval.py`，`--only` 选单个任务，`--seed` 固定随机性；默认不跑（要花钱）。

**代价**：跑一次全量约 30～60 万 token。

**注意**：DeepSeek 的 `seed` 只是「尽量」可复现（同一 seed 两个脚本跑出过 11 步和 25 步），
所以断言要留余量，别卡死具体步数。

## 2. 单步流式

**为什么**：现在从发出到第一个动作回来，20～30 秒里界面只有「正在分析…」。
项目卖点是过程可见，这段恰恰是黑的。

**做什么**：

- `agent._call` 改成流式请求（`stream: true`），把 `content` / `reasoning_content`
  的分片通过 SSE 或轮询推到前端。
- 时间线的 live 行接住这些分片，取代现在的 `WAITING_WORDS` 轮换。
- 工具调用仍然整段解析（流式里 `tool_calls` 是增量拼接，要等结束再执行），
  所以「一步一动作」的语义不变。

**代价**：`_call` 要重写并覆盖流式的错误/截断分支；前端加一条事件通道。
现有 47 个测试大多不涉及流式，需要补。

---

## 3. 会话列表 + 轻量鉴权

**为什么**：限流已经做了，但「最近」还只在 localStorage 里，换设备 / 换浏览器就是空首页。
公网访问时这是明显的断点。

**做什么**：

- 服务端按 `IP|client-id` 存一份会话 id 列表（`var/sessions/index.json` 之类），
  提供 `GET /api/sessions`。
- 前端首页「最近」改成读服务端，本地只做缓存。
- 不做完整账号体系：先用设备标识，能跨浏览器看到自己那几场就够。

**代价**：`/api/session` 增加归属概念，`tests/test_api.py` 里直调端点的用例要跟着改。

---

## 4. 早期过程摘要（`dsh-compaction-basic` 的思路）

**为什么**：现在被裁掉的步骤就是彻底丢了，模型只能靠 `look` 重新读。
评测里 seed 42 反复读同一个文件，根因就是「忘了自己写过什么」。

**做什么**：

- 每轮结束（或裁剪发生时），用一次廉价调用把丢掉的那段压成两三句：
  「已建 index.html / style.css / script.js；style.css 改过背景色两处」。
- 这条摘要作为一条 user 消息插在历史最前面，随裁剪一起滚。
- 注意别让它进 system（前缀一变，上下文缓存全失效，见 HANDOFF 7.6）。

**代价**：每次裁剪多一次模型调用（约 1～2k token），换来更少的无效 `look`。要实测净收益。

## 顺带要修的小账

1. `agent._TOKENS` 是模块级全局变量，两个会话并发时互相覆盖，导致用量少记。
   改成挂在 `Session` 上，或用 `contextvars`。
2. `var/sessions/*.json` 没有清理策略；`POST /api/session` 不查额度，
   公网可被刷盘。至少加个「按修改时间删 7 天前的文件」。
3. `session.MAX_MESSAGES = 80` 是落盘裁剪，和发给模型的 20 条是两回事，
   改的时候别混。
