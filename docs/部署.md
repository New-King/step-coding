# 部署

一台机器、一个进程、一个端口。页面和 `/api` 同在 **8790**，前面由 1Panel 的站点反向代理接域名和 HTTPS，
浏览器看到的是同源请求 —— 和本地 `http://127.0.0.1:8790` 完全一样（打字效果在前端本地跑，不依赖服务端流式）。
全程只在「运行环境」+「网站」两个地方点，不装 Docker。

## 资源占用

| 项 | 量 |
|---|---|
| 内存 | 常驻约 50MB（uvicorn 单进程 + 最多 12 个会话缓存） |
| CPU | 基本空闲，只在等模型接口 |
| 磁盘 | `.venv` 约 100MB + `web/dist` 约 300KB + `var/sessions` 按量（一次会话几十 KB） |

真正的等待在 DeepSeek 接口那一侧，不在自己服务器上。**不需要单独开机器，不需要 Docker**
（容器本身还要额外 100～200MB）。

## 前提

- Python 3.9+（本机 3.9.6 已验证）
- Node 20 + pnpm（只在服务器上构建前端时才需要）
- 一个域名解析到服务器

## 一、放代码、装依赖

代码放哪都行，路径别太长、别放在面板的静态站目录里。1Panel 上最省事是走面板的「文件 → 终端」，直接在 `/opt/step-coding` 下操作：

```bash
sudo mkdir -p /opt/step-coding && sudo chown "$USER" /opt/step-coding
git clone <repo> /opt/step-coding
cd /opt/step-coding
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

走第四节 A 让面板托管时，虚拟环境交给面板创建也行，那就跳过最后两行。

## 二、`.env`

```bash
cp .env.example .env
```

填 `DEEPSEEK_API_KEY`（联网搜索默认也用这个 key）。

**去调 `.env` 里的行内注释**：`.env.example` 为了好读写的是 `LLM_TIMEOUT=180       # 单次调用超时（秒）`，
而后端只按 `=` 切分、值里不剥注释，`int("180   # ...")` 会失败并**静默回落到默认值**。
要改就写成一行一个：

```ini
DEEPSEEK_API_KEY=sk-xxx
LLM_TIMEOUT=180
LLM_MAX_TOKENS=6000
```

## 三、构建前端

```bash
cd web && pnpm install && pnpm build
```

`web/dist` 在 `.gitignore` 里，**不会跟着仓库过来，必须构建**。
服务器上不想装 Node，也可以本地 `pnpm build` 后把 `web/dist`（约 300KB）传上去。

没有 `web/dist` 时后端只挂 `/api`，`/` 直接 404。

## 四、托管进程

服务器是 1Panel，两条路都行，**A 更省事**。面板「运行环境」里没有 Python 这一项（有些版本只给 Node/Java）就直接用 B，B 和面板不冲突。

### A、面板托管（1Panel「运行环境 → Python」）

在「运行环境」里新建 Python 实例，字段名以面板实际表单为准（各版本略有差异），关键是这几项：

| 字段 | 填什么 |
|---|---|
| 项目目录 | 代码目录（`backend/` 的上一级，`requirements.txt` 在同级） |
| 启动命令 | `uvicorn backend.main:app --host 127.0.0.1 --port 8790`（面板用自己建的 venv 时走这个；要写绝对路径就是 `<项目目录>/.venv/bin/python -m uvicorn ...`） |
| 端口 | `8790`，必须与启动命令一致 |
| 依赖 | 勾「安装依赖」，让它跑 `pip install -r requirements.txt` |
| 外部访问 | **不勾**，只走反代 |

启动后在实例「日志」里应看到 `Uvicorn running on http://127.0.0.1:8790`。
面板若默认生成 gunicorn + 多 worker（`-w 4` 之类），改成单进程 —— 原因见本节末尾。

### B、手工 systemd（想让面板只管反代时）

`/etc/systemd/system/step-coding.service`：

```ini
[Unit]
Description=Step Coding
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/step-coding
ExecStart=/opt/step-coding/.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8790
Restart=always
RestartSec=2
Environment=PYTHONUNBUFFERED=1
NoNewPrivileges=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data /opt/step-coding/var
sudo systemctl daemon-reload
sudo systemctl enable --now step-coding
systemctl status step-coding
```

两条硬约束：

- **只能单 worker**。会话缓存活在进程内存里，`step_lock` 是 `threading.Lock`；开多 worker 会让同一会话落到不同进程，锁和 seq 幂等都失效。默认就是 1，别加 `--workers`。
- **端口不对外**。`--host 127.0.0.1`，公网只走面板的反向代理。

## 五、站点与反向代理（1Panel「网站」）

1Panel 的网站跑的是 OpenResty（Nginx），不是 Caddy，配法不一样：

1. 「网站 → 创建网站」→ 类型选**反向代理**（不要选「静态网站」，静态站会自己接管 `/`，`/api` 会走不到后端）
2. 代理地址填 `http://127.0.0.1:8790`
3. 建好后打开该站的「配置文件」，在反代那段补上超时：

```nginx
proxy_read_timeout 200s;
proxy_send_timeout 200s;
proxy_buffering off;
```

三条都不是可选：

- `proxy_read_timeout`：Nginx 默认 **60s**，而模型单次调用超时是 `LLM_TIMEOUT=180`，不改的话一轮跑到 60 秒就被切断，前端表现为「这一轮突然断了」。
- `proxy_send_timeout`：同理，请求体不大但这个方向也别卡在默认值。
- `proxy_buffering off`：关掉响应缓冲，首字节能更早到前端。

前端里没有任何写死的地址：页面、`/assets`、`/api` 全部同源走域名，所以反代配好就与本地一致（打字效果本来就在浏览器本地跑）。

**不要在 1Panel 里给 8790 开「外部端口」/放行防火墙** —— 站点反代就够，端口只留本机监听。

## 六、上线前清数据

`var/` 是本地跑出来的会话，不进仓库；但如果是 rsync 整个目录上来，会把测试数据一起带上去：

```bash
rm -rf /opt/step-coding/var/sessions/*
```

清完再用 `/api/health` 和首页各验一次，然后才让第一位用户进来。

## 七、检查清单

- [ ] `curl -s localhost:8790/api/health` → `configured: true`（`false` = key 没读到）
- [ ] 打开首页 → 说一句话 → 能看到思考 / 查看 / 写文件的逐步动作
- [ ] 跑到一半点「暂停」，再点「继续」，能接上
- [ ] 点「返回」再进「最近」，能恢复现场（说明服务端会话在）
- [ ] 实例日志（面板「日志」按钮，或 B 方式下 `journalctl -u step-coding -f`）只有访问日志，没有 traceback
- [ ] 删掉一条「最近」记录 → `var/sessions/` 里对应文件同时消失（写权限正常）

## 八、常见问题

| 现象 | 原因 |
|---|---|
| 首页 404、`/api/health` 正常 | `web/dist` 没构建或没传上去 |
| `configured: false` | `.env` 不在项目目录下，或 key 为空 |
| 一轮跑 60 秒后突然断 | 反代 `proxy_read_timeout` 还是默认 60s，见第五节 |
| 一轮报 502 | 模型接口超时 / 报错，看实例日志里的 detail |
| 刷新后会话没了 | `var/sessions` 没写权限 —— `Session.save()` 会吞掉 `OSError`，`chown` 给服务用户即可 |
| 同一轮被执行两次 | 起了多 worker，回退成 `--workers 1` |

## 备份

`var/sessions/` 直接 tar 就行；丢了也不致命 —— 前端 localStorage 里还有一份现场，能重新同步回服务端。

## 附：实测记录（2026-11-20）

- 用方式 B（systemd），代码从本机 `rsync` 直传 —— 服务器上 `git clone` 会 `RPC failed; curl 16 Error in the HTTP2 framing layer`。
- 前端在本机 `pnpm build`，`web/dist` 随 rsync 一起上去；服务器不装 Node。
- 服务器缺 `python3.10-venv`，先 `apt install python3.10-venv`。
- 1Panel 的 OpenResty 跑在容器里（`docker ps` 里的 `1Panel-openresty-xxx`），改完配置要 `docker exec <容器名> openresty -s reload`，宿主机的 `systemctl reload openresty` 不生效。
- 实测常驻内存 50MB，代码 + `.venv` 共 59MB。
